# 部署与待接入项

本轮只交付独立进程代码、静态页面、客户端及隔离验收。未安装 systemd、未替换原站二进制、未改配置/域名/防火墙、未重启服务。

建议最终采用**独立 HTTPS 子域名 + 回环 8890**，由现有入口维护者明确提供 TLS/反向代理；该仓库当前主站是自己终止 TLS，并不存在可直接复用的通用远程 App 代理。服务只绑定显式回环，HTTPS Origin 由配置锁定，反代保留原 Origin、不得将管理员接口开放跨域。不要直接暴露 8890 到公网，也不要修改原站 IPv4/IPv6 443 监听。实际域名与证书/反代责任人须部署时确定，本文不擅自配置。

独立运行账户应只能访问自己的 `/var/lib/ai-player-portal/` 数据/凭据目录，目录 0700、配置及凭据 0600、进程不需 root。可执行文件部署到独立路径（如 `/opt/ai-player-portal/`），不得覆盖 `bin/mineagent`。以仓库锁定 Go 依赖构建，静态资源已嵌入，生产无需 node_modules。

## 备份责任与恢复

**负责人：部署本独立服务、持有其 OS 账户的站点维护者。** 审核负责人为其创建的本服务管理员。未部署前没有新增数据库的生产备份作业；不推断其他项目或本机已有备份。正式上线前维护者应明确值守人员并创建下述任务，本轮不安装调度。

2026-10-20 已只读核查当前用户 crontab（1 项）与可见 systemd timers（19 项），未发现 aiplayer/ai-player-portal 相关调度。此结论仅限上述范围，不代表其他管理员或外部调度系统不存在备份。

建议每日一次，备份到非临时且与运行数据分开的 `/var/backups/ai-player-portal/<UTC日期>.db`（目录仅备份账户可读），保留 30 天，并保留需要的异机副本；存储位置、保留期与异机凭据由维护者确认。使用 `aiplayerportal --config <独立配置> --action backup --output <新绝对路径>`，文件已存在时拒绝覆盖。CLI 禁止 /tmp 作为正式备份目的地。

定期恢复演练：复制一份备份到新测试目录；使用新的配置文件、回环端口、Origin 和数据库路径；运行 integrity_check，核对文章、工作版本、审核和幂等记录，再启动该独立服务验证只读与管理流程。恢复正式服务需单独维护窗口：停止**该独立服务**、保存旧数据库及 WAL/SHM、切到验证过的新文件再启动，不直接覆盖打开的 SQLite，不影响 MineAgent/Paper。备份中包含管理员密码摘要及会话/AI token 摘要，仍须保密；正式灾难恢复后建议重设管理员密码和轮换写作/资料凭据。

## 运维与异常

`GET /healthz` 仅检查本服务数据库；`/api/ai-info` 的 profileConfigured 只表示配置存在，不表示来源健康或 MineAgent 工具已接入。源连接错误只记录固定告警事件/HTTP 状态，不打印 URL、凭据或正文。401/403 修复凭据文件后，维护者按独立服务流程重启它；不会因此恢复文章任务或身体动作。

数据库应用标识不匹配时拒绝启动，不尝试迁移 MineAgent 数据；本服务 V1 schema 无原站迁移步骤。内容退役可先隐藏相关文章/封禁写入；服务回滚只涉及自身独立二进制/数据库维护流程。超出 30 天的软删物理清理、审计/幂等/配额的存储归档属于后续运维，不在 V1 自动执行。
