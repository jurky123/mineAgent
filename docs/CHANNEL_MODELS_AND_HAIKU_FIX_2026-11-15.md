# 渠道默认模型与 QQ Haiku 调用修复

## 故障证据与处理

群内显式选择 `claude-haiku-5-5` 后，请求在摘要阶段失败，上游返回 `Invalid assistant message: content or tool_calls must be set`。只读统计 QQ 会话存在14条空助手历史，当前选中Haiku会话的实际摘要后上下文中有2条；不删除、不改写生产历史。

代码另有独立问题：回复模型采用用户选择，`runnerFor` 的摘要中间件却始终绑定站点默认模型。因此日志虽然显示当前选择 Haiku，实际失败的摘要请求仍走默认模型。

修复：构造模型历史时跳过没有正文/持久化工具调用的空助手记录；摘要与回复统一使用当前请求解析后的模型；直接模型/思考选择不再被 MC runner 快速路径忽略。保持正常消息和已保存历史，保留群当前的显式 Haiku 选择，不要求 `/new`，不自动更换模型或重放旧任务。

真实 API 仅使用少量合成文本验证，带正式代码已使用的网关会话头：默认模型遇到空助手输入复现400；清理后200，约1.37秒；Haiku 清理后200，约0.99秒。Haiku本身能接受本次最小空输入，不能据此把线上摘要错误归因于Haiku权限或缺模型。未读取/发送真实聊天正文，未向QQ投递测试消息，未授予工具权限。精确结果见私有证据 `summary-provider-probe.log` 与 `haiku-probe.json`。

## 网页入口与优先级

**Agent 设置 → 渠道设置 → 选择渠道 → 默认模型**。支持网页、QQ、企业微信、企微智能机器人、个人微信和 Minecraft 聊天。管理员才能修改；普通用户继续只有个人偏好。

优先级：显式会话/网页账号模型 > 渠道默认 > 站点默认。QQ `/model default` 清除会话覆盖后跟随渠道设置，群自然接话沿用同一规则。更改在提交下一条新请求时确定，已经排队/运行的任务保持原模型。网页渠道更改后刷新当前页面的模型标签，不清除草稿或个人选择。

选择器复用现有目录，标记/禁用缺密钥与不可用条目。保存时后端重新校验新ID，不接受任意注入；已保存但暂未列出的当前模型可保留，其他设置不被目录暂时失败阻塞。模型列表失败时保留模型并禁用修改，原人设/规则仍可编辑。

模型与渠道规则、人设一起原子写入现有 `prompts.json` 的 `serviceModels`；写盘失败整体回滚。旧客户端不传 `model` 时保留原值，空字符串恢复跟随站点。无需数据库迁移，不改变身份、工具或审批权限。
